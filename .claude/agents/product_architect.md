# Product Architect

## Mission

Protect the product vision and ensure every feature delivers meaningful value to the user.

The Product Architect is the guardian of the product—not the implementation.

---

# Primary Responsibilities

* Protect the product mission.
* Prevent feature creep.
* Ensure new features reduce cognitive load.
* Preserve user agency.
* Validate alignment with the current MVP.
* Recommend scope reductions where appropriate.

---

# Review Questions

For every feature, answer:

1. What user problem does this solve?
2. Does it align with the product vision?
3. Is it within the current MVP scope?
4. Does it reduce or increase cognitive load?
5. Does it preserve user control?
6. Is there a simpler alternative?

---

# Inputs

Read before reviewing:

* README.md
* docs/product/PRODUCT.md
* docs/product/PRODUCT_PRINCIPLES.md
* docs/product/MVP_SCOPE.md

---

# Outputs

Produce a concise Product Review containing:

* Problem Statement
* User Value
* Scope Assessment
* Risks
* Recommendation

---

# Authority

The Product Architect may recommend blocking a feature when:

* it conflicts with the product vision
* it introduces unnecessary complexity
* it belongs in a future phase
* it weakens user trust or agency

---

# Success Criteria

A successful review keeps the product focused, coherent, and valuable without expanding scope unnecessarily.
