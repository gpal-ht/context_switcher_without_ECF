# Domain Model

## Purpose

This document defines the core concepts of the Context Switcher domain.

These are business concepts, not implementation classes.

The domain model should evolve before implementation begins.

---

# Core Philosophy

The application manages **work context**.

Projects, tasks, notes, sessions, AI recommendations, and productivity insights all exist to preserve and improve work context.

Context is therefore the central concept of the domain.

---

# Core Domain Concepts

## Workspace

Represents the user's complete working environment.

Initially, a workspace belongs to a single user.

Future versions may support multiple workspaces.

---

## Project

A meaningful body of work.

Examples:

* Context Switcher
* Personal Finance
* Learning WinUI
* Home Renovation

A project provides long-term continuity.

---

## Work Session

A bounded period of focused work.

A session has:

* start
* end
* duration
* objective
* outcome

A project contains many work sessions.

---

## Context

The information required to resume productive work.

Context may include:

* goals
* current objective
* recent decisions
* blockers
* assumptions
* open questions
* relevant notes
* important links

Context changes continuously.

---

## Context Snapshot

A snapshot captures context at a specific point in time.

Snapshots allow future reconstruction of work.

They are expected to become one of the application's most valuable assets.

---

## Wrap-Up

The structured reflection performed at the end of a work session.

Typical information:

* completed work
* unfinished work
* blockers
* future-self notes
* next action

---

## Resume Brief

The information presented when returning to a project.

Initially:

* previous wrap-up
* unfinished work
* blockers

Future versions may include AI-generated summaries.

---

## Decision

A meaningful decision made during project work.

Decisions are often more valuable than notes because they capture reasoning.

---

## Note

General information recorded during work.

Notes are lightweight.

Not every note is a decision.

---

## Blocker

Something preventing progress.

Blockers should be visible until resolved.

---

## Next Action

The smallest meaningful piece of work that should happen next.

The application should always know the current Next Action.

---

## AI Recommendation

A suggestion generated by AI.

Recommendations never modify user data automatically.

They exist to support decision-making.

---

## Insight

A higher-level observation derived from historical work.

Examples:

* frequent interruptions
* recurring blockers
* estimation accuracy
* focus trends

Insights emerge over time.

---

# Domain Relationships

Workspace

→ contains Projects

Project

→ contains Work Sessions

Work Session

→ produces Wrap-Up

Wrap-Up

→ updates Context

Context

→ creates Context Snapshot

Context Snapshot

→ becomes Resume Brief

AI Recommendation

→ analyzes Context

Insight

→ analyzes historical Context and Work Sessions

---

# Domain Principles

1. Context is more valuable than tasks.
2. Decisions are more valuable than notes.
3. Resume speed is more valuable than information quantity.
4. AI supports understanding, not authority.
5. Every work session should improve future context.

## External Context Source

A source of work context imported from outside the application.

Examples:

- ChatGPT conversation export
- project notes
- GPT instructions
- manually imported documents
- future integrations

External context is not automatically trusted. It must be parsed, summarized, and mapped into the application's own domain model.

---

## ChatGPT Context Import

A special type of External Context Source representing user-provided ChatGPT data.

Potential imported material:

- recent chats
- project-related conversations
- GPT instructions or descriptions, where available
- exported conversation history
- user-provided summaries

The application may use this information to help:

- reconstruct project context
- identify active projects
- extract decisions
- identify blockers
- suggest next actions
- improve context-switch recommendations

The application must not assume direct access to ChatGPT Projects, GPTs, or full account state unless an official supported export/API exists and the user explicitly authorizes it.

## Session Outcome

Every Work Session ends with a Session Outcome.

The outcome records what happened during the session, independent of whether the original goal was achieved.

Possible outcomes include:

- Completed
- Partially Completed
- Blocked
- Replanned
- Cancelled
- Superseded
- Interrupted
- Research Completed
- Decision Reached

Every outcome contributes knowledge to the system.

The goal of a session is to improve understanding, not merely complete tasks.
