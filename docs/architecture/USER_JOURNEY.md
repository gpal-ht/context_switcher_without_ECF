# User Journey

## Purpose

This document describes how a user interacts with Context Switcher throughout a typical workday.

The goal is to design the user's experience before designing screens or implementation.

---

# Core Work Loop

The application supports a continuous cycle:

1. Prepare
2. Plan
3. Execute
4. Capture
5. Evaluate
6. Transition
7. Resume

Each completed work session enriches the user's knowledge and improves future context.

---

# Morning Startup

The user opens Context Switcher to begin the day.

The application presents:

* Today's active projects
* Outstanding work from previous sessions
* Unresolved blockers
* Recent decisions
* AI-generated morning briefing (future capability)
* Suggested priorities (future capability)

The user decides what to work on.

---

# Session Planning

Before starting a work session, the user defines intent.

Examples:

* Fix authentication bug
* Design AI architecture
* Review pull request
* Implement timer service

The session plan may include:

* expected outcome
* estimated duration
* success criteria
* repository (optional)
* branch (future)
* related documents

The application records expectations before work begins.

---

# Focus Session

During the session, the application minimizes interruptions.

It may provide:

* countdown timer
* remaining time
* subtle reminders
* optional note capture

The user remains focused on the selected project.

---

# Wrap-Up

Near the end of the session, the application prompts reflection.

The user records:

* completed work
* unfinished work
* blockers
* important decisions
* notes for future self
* next action

The goal is to make the next session easier to begin.

---

# Repository Evaluation (Future Capability)

If the session is linked to a local Git repository, the application may analyze:

* commits
* changed files
* test results
* build status
* code quality signals

AI may compare actual work against the original session plan.

The evaluation should include:

* evidence
* confidence
* assumptions
* completion estimate
* quality observations

The user decides whether the evaluation is accurate.

---

# Context Transition

When changing projects, the application helps the user leave one context cleanly before entering another.

The transition should feel calm and intentional.

The user should not need to mentally reconstruct work later.

---

# Context Resume

When returning to a project, the application presents a concise resume brief.

Examples:

* previous objective
* last completed work
* unfinished work
* blockers
* decisions
* next action
* relevant notes
* AI summary (future capability)

The objective is to resume productive work within minutes.

---

# Continuous Learning

Over time, the application develops a better understanding of the user's work.

It may identify:

* recurring blockers
* planning accuracy
* focus patterns
* context-switch frequency
* estimation trends

Insights should help the user improve, not judge them.

---

# Design Principles

The journey should always:

* reduce cognitive load
* preserve user agency
* make AI recommendations explainable
* encourage intentional work
* respect privacy
* improve future sessions through better context

---

# Future Journey Extensions

Potential future capabilities include:

* ChatGPT context import before starting a session
* GitHub repository awareness
* IDE integration
* Calendar awareness
* Meeting preparation
* End-of-day review
* Weekly retrospectives
* Cross-project dependency insights

These capabilities should strengthen the core work loop without increasing unnecessary complexity.
